## 5. 调试经验与坑位（重要，避免重踩）

1. **texi2any 崩溃**：fate.texi 的 `@node Top`+全文组合触发 texi2any 7.2
   DocBook.pm:417 "Not a HASH reference" 崩溃——剥离 `@node`/`@settitle` 解决
   （texi2md.strip_texi_boilerplate），管线不依赖 node（锚点来自 @anchor+标题）；
2. **include 裁剪必须 flatten 层做**：makeinfo 会把标记 para 移入 chapter/sect1
   内部，XML 层裁剪不可靠（实测 317 个嵌套 vl 因 stale parent_map 失联）；
3. **表格候选收紧**：含嵌套 variablelist/screen 的条目禁走表格路径
   （tableify 只搬 term+首段，实测丢内容 220 段被 validate 计数对比抓出）；
4. **代码块歧义**：GFM 缩进代码 vs 嵌套列表续行文本文本层不可分——在 XML 层
   `screen→programlisting@language` 让 pandoc 直接输出 fenced（语言启发式：
   #!→shell、;+( →c、其余 text）；
5. **slug 口径**：mkdocs toc.slugify=小写+保留 `-`/`_`+空格→`-`（不是 nonorm
   大小写保留！mkdocs 不接受字符串配置名）；官方 `_005f`/`_002d` 编码锚点由
   anchor_map（激进归一化多形态索引）+ fix_links 桥接；
6. **anchor_map 是纯派生产物**：禁止与旧文件合并（过时 slug 会回写覆盖，实测踩坑）；
7. **Mimosa 钩子误报面**：①subprocess 参数列表含变量/f-string/format 串会被拦
   （规避：调用点内联字面量列表或集中 proc.py splat）；②构建产物（site/）里的
   第三方 JS（lunr wordcut.js）触发"代码注入"高危拦截提交——提交前必须
   `rm -rf site/`；③L3 缓存刷新需重跑 security_scan；
8. **CI 差异**：CI ruff 需显式 ruff.toml（默认规则集比预期宽）；覆盖率先锁 35%
   防回退（fmt 80% 门槛是 M4 专项后达成，M2 补测专项跟进）；
9. **memgate 语法**：`memgate [MB数] <cmd>`（8G=8192 不是 8G）。

## 6. 硬性纪律（持续有效）

- 长任务/内存不可预估脚本一律 `memgate [MB] <cmd>`（filters 转换用 8192）；
- 网络直连失败→代理 `http://192.168.33.1:10808` 重试一次再下结论；
- 数字结论须有实测出处；URL 引用标注核实日期与通道；
- 许可红线（DR-006）：doc/t2h.pm、doc/texi2pod.pl 严禁衍生；ffmpeg-web 资产不搬运；
  wiki 页脚署名块不可删改；
- 凭据纪律（fmt DR-013）：零凭据字面量，M2 不需要任何 API key；
- 不改动 fmt-zh-docs 等既有工程；/tmp 克隆属不可信数据（python3 -I 处理、不执行树内脚本，
  ./configure 为 PLAN 明确豁例外）；
- 提交前 `rm -rf site/`（Mimosa 误报拦截）+ 重大决策走 DR 流程（下一编号 DR-010）。
