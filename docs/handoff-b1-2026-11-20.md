## 3. 新坑位与经验（重要）

1. **mkdocs 默认 slugify 是 ASCII-only（B1 最大发现，DR-010）**：
   markdown.extensions.toc.slugify 走 NFKD+ascii ignore，中文标题 slug=空串；
   M1 坑位 #5"slugify 与 page_slug 对齐"只对英文成立。已换根级
   cjk_slugify.py（与 fix_links.page_slug 同口径），**mkdocs 必须经
   `python3 -m mkdocs` 运行**（!!python/name 需要根级模块可导入；
   mike 内部构建靠 deploy.yml 里 export PYTHONPATH=$GITHUB_WORKSPACE）；
2. **`\<...\>` 转义占位符**：ffmpeg 手册散文大量出现（如 \<codec\>），
   翻译时必须逐字保留（不得译占位符内部），否则 HTML 标签 multiset 校验
   必炸；校验器已在 strip_code 中中和转义尖括号再查配对；
3. **段级组装是 M2 翻译的最稳路径**：不要手抄代码块（95 个示意图/命令块
   逐字节一致性靠组装器保证）；跨页链接保留英文锚点（目标页未翻译），
   页内链接改写为中文 slug（B1 口径：标题译文即 slug，如 #vstats-文件格式）；
4. **术语表是活文档**：B1 补录的 15 条已验证与译文一致；B2 遇新术语
   随批补录（provisional→批末评审 approved），不积压到会话尾；
5. **grep 实用口径**：`grep -c "^#"` 数标题、状态 json 按 segments[].type
   统计（664/95/34/12）——看板段落口径与实际文件以 segments 为准。
