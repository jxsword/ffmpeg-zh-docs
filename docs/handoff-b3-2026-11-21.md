## 3. 新坑位与经验（重要，避免重踩）

1. **Write 长内容生成异常本会话复发并恶化**（本会话最大坑位）：
   scaler/resampler 的长 Write 译文块出现四类故障：占位文本泄漏（"保留原文"/
   "translation placeholder"）、外来字符串入（"contaminated output"/"污染的输出"）、
   同块重复多次、mojibake（淿/辷/涿/挍）与 stray 英文句注入。
   **对策（已验证有效）**：译文块改用 **Bash heredoc 写 /tmp tr 文件**
   （Mimosa 对 /tmp 非源码文件不受限；与 Write 路径完全不同的生成路径，
   本会话 heredoc 全程零异常），每文件 ≤10 块，写完立即 cat 目检；
   解析器 last-value-wins 只是兜底，不可依赖。
2. **异常串扫描模式要随会话更新**：B2 的扫描模式在本会话新增了实测特征串
   （contaminat/污染的输出/正确内容/stray sentence/mojibake 字符集等），
   三重检查的异常扫描应把当会话见过的故障特征都收进去。
3. **索引错位**：codecs 1223 起跳译两段（nr/static-thresh）未补位，导致
   @@ 索引整体 -2 错位约 50 段，靠组装前 coverage check 抓出（missing/extra/
   empty）。对策：跳译任何段时立即补位；错位后用脚本按段真值重排
   （/tmp/b3-work/fix-1214.py 模式），不要手工逐块 Edit。
4. **M1 占位页入库形态是"构建回写后的快照"**：英文占位页带着 anchor_map
   的回写结果入库（如 codecs 占位页含 `codecs.md#description` 错误回写）。
   因此**译文页首次提交前绝不能用 git checkout 还原**（会退回英文占位页，
   译文直接丢失）——组装后先 cp 备份到 /tmp，构建验证后用 cp 恢复组装稿；
   只有已提交的译文页才可用 git checkout 还原构建回写。
5. **Mimosa 新误拦面**：①compound 命令同时含 `cp` 与 `scripts/*.py` 路径字样
   会整条被拦且**整条不执行**（B2 坑位⑥的变体）；②site/ 残留触发 L3 高危
   拦截 commit（M1 坑位⑦②），且 PreToolUse 拦截连坐整条 compound 命令——
   `rm -rf site/` 必须在独立命令中先执行并确认成功。
6. **state 文件序列化**：库内为 indent=2；重新序列化时保持 indent=2 + 末尾
   换行，否则 diff 全文件爆炸。校验器口径是**段级 status**（file-level status
   键不存在，误加会被覆盖无害但不要加）。
7. **B4 预警（anchor_map 抽查）**：formats.md 体量与 codecs 同级，翻译前先
   抽查 anchor_map 中 formats 相关锚点→slug 映射是否正确（codecs 的
   codec_002doptions→description 错位说明 M1 转换器存在标题-锚点错位缺陷，
   formats 可能同病）；可疑即 heading-bridge 随批登记，不修 anchor_map
   （派生产物，sync 会重建）。
