# FFmpeg 中文翻译项目前期调研大纲（v3 · 三轮复审终稿）

> 落盘：2026-11-19（规划会话）｜执行：新会话（按 `docs/handoff-2026-11-19.md` 交接）
> 已定决策依据：`docs/decision_log.md` DR-001~005

## 1. 背景与目标

- 背景：新建 ffmpeg-zh-docs 工程，将 FFmpeg 官方文档（https://ffmpeg.org/documentation.html）全类别译为中文，git 管理、跟随官方持续增量更新、支持增量翻译。五项关键决策已确认（DR-001~005）：GitHub 公开仓+Pages｜基线=最新稳定 release｜载体=texi→md+mkdocs 流水线｜wiki=精选｜API=注释翻译+Doxygen 重建。
- 目标：
  1. 摸清全网（GitHub 优先）已有的 FFmpeg 官方文档中文翻译项目，产出优缺点分析与**组件级**可借鉴/可复用清单；
  2. 核实 FFmpeg 文档体系与许可条款，为翻译计划（下一步制定）提供量化与合规输入。

## 2. 调研对象清单（含链接三件套核实清单）

- **主对象**：以 FFmpeg 官方文档为底本的整站/整册中文翻译项目（预计 2~5 个）。判定标准：以官方文档为底本的整站/整册翻译；排除零散教程片段、视频课程、纯笔记。
- **参照对象（可选）**：非中文的官方文档翻译项目（如日语翻译站）——仅当中文候选不足或其机制突出时纳入方法论借鉴。
- **佐证对象**：FFmpeg 文档体系本身（子任务 S2）。
- **搜索入口**：
  - GitHub：关键词组 `ffmpeg 中文文档` / `ffmpeg 中文手册` / `ffmpeg 手册` / `ffmpeg 翻译` / `ffmpeg chinese documentation` / `ffmpeg docs chinese`；`in:readme` 组合检索；topic 检索；
  - Gitee、GitCode 搜索同名关键词；
  - awesome-ffmpeg 等聚合清单；
  - FFmpeg trac wiki（trac.ffmpeg.org）中的翻译链接；
  - 中文社区文章（博客/CSDN/知乎）提及的项目线索（仅作发现渠道，不作为对象本身）。
- **已核实官方 URL**（2026-11-19，直连+代理双通道 `git ls-remote` / curl，均可达）：
  - 正文与文档源码仓：`https://git.ffmpeg.org/ffmpeg.git`（镜像 https://github.com/FFmpeg/FFmpeg，HEAD 一致）
  - 网站源码仓：`https://git.ffmpeg.org/ffmpeg-web.git`
  - 文档导航页：`https://ffmpeg.org/documentation.html`（官方无任何中文版本，已查证）
- **候选核实清单**：每个候选仓库 URL、宣称的在线站点 URL、许可证声明出处——全部实测可达后才可引用；死链用 Wayback Machine 快照兜底并注明。

## 3. 调研维度与比较框架

① 活跃度（最后提交/star/fork/贡献者，数字须实测出处）② 覆盖范围（对应官网哪些类别、哪个版本基线）③ 翻译完整性与质量口碑 ④ 上游对齐与增量机制（有无自动化）⑤ 技术实现（载体格式/站点/流水线）⑥ 许可合规声明 ⑦ 多版本/历史版本处理 ⑧ 是否覆盖 API/Doxygen ⑨ 站点可达性（含国内网络）⑩ 对本计划的组件级可借鉴/可复用点 ⑪ 差异化机会点。

- **存活判定**：最后提交 ≤24 个月 = 存活候选（深度分析）；>24 个月 = 历史参照（仅记录，不深析）。
- **选择策略矩阵模板**（总报告须含）：

```markdown

|---|---|---|---|
| <维度①~⑪ 关键差异项> | | | |
| 适用场景判断 | | | |
```

矩阵后必须给出按场景的选择结论：谁能直接用 / 谁可借鉴什么 / 我们为何自建。

## 4. 并行子任务拆分（两个后台子代理并行）

- **S1（子代理一）**：按第 2 节搜索入口全网搜索 → 筛选（存活判定；候选 >5 时按存活+活跃排序取前 5）→ 深度分析（维度①~⑩，每个候选链接三件套+实测）→ **产出文件：`research/ffmpeg-zh-projects-候选搜索与分析.md`**（逐条套用对象条目模板，含每个候选的保留/放弃判定与理由）。
- **S2（子代理二，与 S1 并行，互不依赖）**：FFmpeg 文档体系与许可核实：
  1. `doc/` 全量清单与**体量表**（每个 `.texi` 行数/词数，→ 翻译工作量估算输入）；
  2. makeinfo / Doxygen 构建链与版本要求；
  3. **许可核实**：`.texi` 文件头 `@copying` 许可声明原文摘录、LICENSE/COPYING.* 对文档的说明、`ffmpeg-web.git` 网站内容许可、trac wiki 内容许可、Doxygen 注释许可随源码的 GPL/LGPL 分布；
  4. release 节奏（最近 major/point tag 日期与间隔）；
  → **产出文件：`research/ffmpeg-doc-体系与许可调研.md`**。
- **失败预案**：各子代理失败重试一次；仍失败则降级为主会话顺序执行并记录现象，不阻塞整体。
- **风险登记**：GitHub API 匿名限额 60 req/h——节制调用，优先 gh api（若本机已认证）或 `git ls-remote`/网页实测；git.ffmpeg.org 直连有超时先例——按全局网络回退纪律处理。

## 5. 汇总合并方式与后续

- 主会话合并两份子报告 → **`research/ffmpeg-zh-projects-调研报告.md`**：对象条目（三件套模板）+ 各自优缺点 + 适用场景 + 选择策略矩阵（含"直接用/借鉴什么/为何自建"结论）+ 组件级借鉴清单 + 对 ffmpeg-zh-docs 的差异化定位。

## 6. 纪律与风险

- 所有 URL 实测可达才可引用，标注核实日期与通道（直连/代理）；直连失败按全局约定走代理 `http://192.168.33.1:10808` 重试一次。
- 数字类结论（star/提交日期/体量）必须有实测出处。
- 调研产出文件名只允许英文字母、数字、汉字、`_`、`-`。
- 长任务/内存不可预估脚本一律 `memgate` 包裹（缺省 4G）。
- 重大决策：决策矩阵 → 用户确认 → 写入 `docs/decision_log.md`（编号取最大 +1）。
